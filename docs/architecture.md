# Архитектура MVP

## Компоненты

```text
MAX bot ───────────────┐
                      │
MAX mini app (React) ─┼── FastAPI ── PostgreSQL
                      │       │
                      └───────┴── notification worker
```

- Бот открывает мини-приложение и доставляет уведомления.
- React отвечает за список игр, карточку, запись, создание слота и «Мои игры».
- FastAPI проверяет данные запуска MAX и содержит бизнес-логику.
- PostgreSQL хранит пользователей, поля, слоты, участие и задания уведомлений.
- Фоновый обработчик отправляет запланированные сообщения через бота.

## Первый сквозной сценарий

1. Пользователь открывает мини-приложение из MAX.
2. Backend проверяет данные запуска и возвращает текущего пользователя.
3. Frontend получает список слотов на ближайшие семь дней.
4. Пользователь открывает слот и записывается.
5. Backend проверяет свободное место и пересечения по времени.
6. Слот появляется в разделе «Мои игры».
7. Пользователь может отказаться, после чего место снова доступно.

## Границы первой итерации

- один район Москвы;
- только футбол;
- поля выбираются из базы;
- хост не редактирует опубликованный слот;
- телефон необязателен;
- платежей, рейтингов, карты и группового чата нет.
