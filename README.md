# PlusOne

Мини-приложение в MAX для поиска футбольных игр рядом и набора участников.

Сейчас в репозитории находится backend-основа MVP: FastAPI, PostgreSQL,
миграции базы данных и API чтения игровых слотов на ближайшие семь дней.

## Запуск

Понадобится Docker с поддержкой Compose.

```bash
cp .env.example .env
docker compose up --build
```

При запуске backend дождётся готовности PostgreSQL, применит миграции и
создаст демонстрационные поля, будущие игровые слоты и участников. Повторный
запуск не создаёт дубликаты.

После запуска доступны:

- API: http://localhost:8000;
- Swagger UI: http://localhost:8000/docs;
- список слотов: http://localhost:8000/slots.

Остановка:

```bash
docker compose down
```

Чтобы также удалить локальные данные PostgreSQL:

```bash
docker compose down --volumes
```

## Тестовые данные

По умолчанию `SEED_DATA=true`, поэтому тестовые данные создаются автоматически.
Их также можно безопасно создать повторно вручную:

```bash
docker compose run --rm backend python -m app.seed
```

Для запуска без тестовых данных установите `SEED_DATA=false` в `.env`.

## Переменные окружения

| Переменная | Назначение | Значение по умолчанию |
| --- | --- | --- |
| `BACKEND_PORT` | Порт API на локальной машине | `8000` |
| `POSTGRES_DB` | Имя базы PostgreSQL | `plusone` |
| `POSTGRES_USER` | Пользователь PostgreSQL | `plusone` |
| `POSTGRES_PASSWORD` | Пароль PostgreSQL | `plusone` |
| `DATABASE_URL` | Строка подключения backend к PostgreSQL | адрес контейнера `postgres` |
| `MAX_BOT_TOKEN` | Токен бота MAX | пусто |
| `MAX_MINI_APP_URL` | Публичный адрес мини-приложения | пусто |
| `SEED_DATA` | Создавать демонстрационные данные при запуске | `true` |

Рабочие токены и пароли не должны попадать в Git. Файл `.env` игнорируется.

## Архитектура

- FastAPI предоставляет HTTP API;
- PostgreSQL хранит поля, слоты и участия;
- Alembic управляет схемой базы данных;
- Docker Compose запускает backend и PostgreSQL одной командой.

Подробная целевая архитектура и основной пользовательский сценарий описаны в
[`docs/architecture.md`](docs/architecture.md).

## Реализованный API

- `GET /slots` — будущие неотменённые слоты на ближайшие семь дней;
- `GET /slots/{slot_id}` — карточка конкретного слота;
- `GET /docs` — интерактивная документация OpenAPI.

## Известные ограничения

- интеграция с MAX, бот и frontend ещё не реализованы;
- пока отсутствуют создание слота, запись, отказ и раздел «Мои игры»;
- уведомления и фоновые задания ещё не реализованы;
- демонстрационные контакты и идентификаторы пользователей являются
  тестовыми данными.
